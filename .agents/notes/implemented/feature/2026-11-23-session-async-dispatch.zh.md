# Agent Note: 会话异步派发偏好

Status: implemented

[English](2026-11-23-session-async-dispatch.md) | 中文

## 问题

复杂任务默认进入看板的通用指令可能覆盖用户希望在当前对话继续工作的意愿。工具栏开关需要改变模型的实际执行指导，同时保持当前任务和权限不变。

## 决策

Conversation 拥有默认关闭的会话投影，分别保存所选值和已入场值。现有人类命令通道只持久保存选择，不调用模型。普通聊天框提交捕获所选值；缺少捕获字段的历史与非 Web 输入按关闭处理。已接受的 pre-step 以最后一条入场人工消息决定必需运行时上下文，直到下一条人工消息入场。重试保留该策略。

进行中的选择写入及已确认目标由共享 Conversation 控制器拥有。提交等待写入完成，并在投影追上前使用已确认值，防止命令回执与投影帧分流到达时误用相反模式。会话身份同时隔离持久投影与待完成操作。

## 考虑过的替代方案

**仅保存界面状态。** 只保存在浏览器的开关不能覆盖现有执行指导，也无法在不同入口和恢复时保持实际含义。

**每个模型步骤读取最新选择。** 点击会改变正在执行的任务，也会把后来的偏好应用于先前排队消息。因此入场时使用各消息提交时捕获的选择。

**新增调度器或工具权限门禁。** 本功能表达偏好，必须允许当次用户明确的看板指令。执行仍由现有看板工具负责，权限仍由现有权限所有者授权。

## 后果

关闭指导明确覆盖按复杂度自动进入看板的规则；开启指导优先派发合适执行任务，普通问答仍直接回复。当次用户明确派发指令可覆盖任一偏好。新会话默认关闭，刷新恢复所选值。实现增加一小段必需运行时上下文和两种纯日志事件，不重启或重派已有任务。持久化结构确认记录了历史缺字段默认值，以及旧读取器对未知事件判别值的安全拒绝。
